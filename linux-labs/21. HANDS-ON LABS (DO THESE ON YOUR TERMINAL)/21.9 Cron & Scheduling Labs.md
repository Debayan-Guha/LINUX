**How Crontab Scheduling Works**

A single `crontab` file can hold **dozens or hundreds of different scheduled tasks** simultaneously.

**Core Concepts**
*   **One File per User**: Every user account on a Linux system gets exactly one personal crontab file managed by the system.
*   **One Line per Job**: You simply add a new line to that single file for every new task you want to schedule.
*   **Independent Schedules**: Each line can point to a completely different script and run on its own independent timetable.

## 21.9.1.11 How Completed Cron Jobs Are Handled

When a scheduled job finishes running, **it is not automatically deleted** from the crontab file. 

For example, if you configure a job to run only on Monday the 19th at 5:00 PM, the system will execute the task at that exact time. Once completed, the entry will permanently remain in your crontab file until you manually open the file and remove it.

**Automating the Deletion**

If you need a job to be removed automatically after it finishes, you have two main options:
- **Self-Deleting Script**: You can append a command to the end of your cron line that automatically edits the crontab file to remove itself once execution finishes.
- **Alternative Tools**: For tasks that only need to run exactly once, using the system's built-in `at` command is generally safer and more efficient than using `cron`.

`/etc/cron.daily` is a predefined system directory in Linux. Any script or executable file you place inside it will automatically run **once every day**.

**Key Rules for Using cron.daily**
*   **No Cron Syntax Needed**: You do not write lines of asterisks (`* * * * *`). You just place a regular, executable shell script directly into the directory.
*   **Root Permissions Required**: Because this is a system-wide directory, you must use `sudo` to add or modify files inside it.
*   **Must Be Executable**: Your script will be ignored unless you give it execute permissions using `chmod +x`.
*   **Strict Naming Rules**: Script names must **not** contain periods (`.`) or extensions like `.sh`. Use `myscript`, not `myscript.sh`.

**Related Predefined Directories**

Linux includes several of these folders out of the box to make scheduling simple:

| Directory | Execution Frequency |
| :--- | :--- |
| `/etc/cron.hourly` | Runs once every hour |
| `/etc/cron.daily` | Runs once every day |
| `/etc/cron.weekly` | Runs once every week |
| `/etc/cron.monthly` | Runs once every month |

**1. What Exact Time Do They Run?**

Unlike a personal user crontab, you do not choose the exact minute these directories run. The system controls the timing using a master file called `/etc/anacrontab`. 

On most systems, daily scripts execute early in the morning (usually between **6:00 AM and 7:30 AM**), or immediately after the computer boots up if it was powered off during the scheduled time.
