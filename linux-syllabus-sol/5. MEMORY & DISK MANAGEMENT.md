# 5.1 Memory Monitoring

## 5.1.2 Understanding buffers vs cache

| Feature | Buffer | Cache |
| :--- | :--- | :--- |
| **Purpose** | Temporarily holds data while it is being transferred | Stores frequently or recently accessed data for faster access |
| **Main Use** | Handle speed differences between two devices/processes | Improve performance by avoiding repeated access |
| **Mostly Used For**| Writes (also streaming I/O) | Reads |
| **Lifetime** | Usually short-lived | Can stay until memory is needed |
| **Goal** | Ensure smooth data transfer | Reduce latency and improve speed |
| **Example** | **Video Streaming:** Pre-downloading upcoming video segments into memory so playback doesn't stutter if your network speed fluctuates. | **Browser Storage:** Keeping a website's static logo on your local drive so it opens instantly next time without a new download. |


## 5.1.6 Swap space usage and tuning

**Swap** is a dedicated disk space (either a partition or a file) that Linux uses as **virtual memory** when physical RAM starts running low. When memory pressure increases, the kernel can move **inactive or less frequently used memory pages** from RAM to the swap area, freeing RAM for applications that are actively running.

Since swap resides on a storage device (SSD or HDD) instead of RAM, it is significantly slower. Therefore, swap should **not** be considered additional RAM. Its purpose is to improve system stability during memory pressure and provide temporary memory overflow.


**Swap tuning** is the process of configuring how Linux manages swap space to achieve the desired balance between **performance**, **memory utilization**, and **system stability**. Instead of simply increasing or decreasing swap size, tuning focuses on controlling **when**, **how much**, and **how aggressively** the kernel uses swap.

The most important swap tuning parameter is **swappiness**.

**Swappiness** is a Linux kernel parameter that determines **how aggressively the kernel moves inactive memory pages from RAM to swap**. Its value ranges from **0 to 100**.

**1. Why Tune Swap?**

Swap tuning allows administrators to optimize the system for different workloads.

- **Desktop systems** often use a **lower swappiness** to keep applications in RAM, resulting in better responsiveness.
- **Database and application servers** usually prefer lower swap usage to maximize memory performance.
- **Memory-constrained systems** may use higher swappiness to reduce the risk of running out of memory.
- Systems with **fast NVMe SSDs** can tolerate swap usage better than systems using slow HDDs, although RAM remains significantly faster.

The optimal configuration depends on the workload, available RAM, storage performance, and application requirements.

**Important Notes**

- Swap improves **system stability**, not application performance.
- Heavy swap usage usually indicates insufficient RAM or excessive memory consumption.
- Increasing swap space does **not** replace physical RAM.
- The best swappiness value depends on the workload and should be tuned based on monitoring system performance.
